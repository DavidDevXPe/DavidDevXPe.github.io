01 / OBJETIVO

Simplificar la exploración de Pokémon

Crear una experiencia de consulta que permitiera encontrar información de Pokémon sin recorrer manualmente todos los resultados disponibles en PokeAPI.

02 / SOLUCIÓN

Un flujo de consulta completo

El flujo comienza con la elección del entrenador y el ingreso del nombre. Después integra búsqueda, filtro por tipo, favoritos y paginación; cada tarjeta presenta el tipo y las seis estadísticas principales.

03 / IMPLEMENTACIÓN

Estado, navegación y datos separados

Construí la interfaz con componentes reutilizables en React, utilicé Redux Toolkit y React Redux para el estado global, React Router para las vistas y Axios para consumir PokeAPI.

04 / DESAFÍO

Coordinar datos asíncronos y controles

El reto fue coordinar búsqueda, filtros, favoritos y paginación con la URL, mientras la caché y la cancelación de peticiones evitaban respuestas obsoletas.

Resultado

Experiencia responsive y accesible publicada en Netlify, con onboarding, exploración detallada y una suite automatizada para validar los flujos principales.

Rick and Morty App

Abrir demo ↗ Ver código
TipoAplicación frontend
Fuente de datosRick and Morty API
PublicaciónNetlify
01 / OBJETIVO

Unificar la exploración del multiverso

Crear una experiencia donde personajes, episodios y ubicaciones pudieran consultarse sin perder el contexto entre colecciones relacionadas.

02 / SOLUCIÓN

Tres colecciones conectadas

Tras elegir a Rick o Morty, el usuario puede filtrar personajes, guardar favoritos, recorrer episodios y consultar ubicaciones con sus residentes paginados.

03 / IMPLEMENTACIÓN

Lógica asíncrona reutilizable

Construí la interfaz con React y la Fetch API. Encapsulé consultas cancelables y listas paginadas en custom hooks, y persistí perfil y favoritos en localStorage.

04 / DESAFÍO

Coordinar modos, filtros y peticiones

El reto fue mantener consistentes la navegación entre colecciones, los filtros, los favoritos y las peticiones cancelables sin mostrar resultados obsoletos.

Resultado

Explorador temático publicado en Netlify, con onboarding persistente, tres áreas de consulta y estados claros de carga, error y resultados vacíos.

CASO DE ESTUDIO 03 / PUBLICADO

ATMOS | App del Clima

Abrir demo ↗ Ver código
TipoAplicación full-stack
Fuente de datosOpenWeather API
InfraestructuraNetlify Functions
01 / OBJETIVO

Hacer accesible el clima de cualquier ciudad

Permitir consultas por nombre o ubicación actual, reuniendo las condiciones esenciales en una experiencia clara y sin depender de un único flujo de acceso.

02 / SOLUCIÓN

Dos formas de consulta, una lectura clara

ATMOS combina búsqueda y geolocalización, adapta su atmósfera visual al clima y presenta temperatura, sensación térmica, viento, nubosidad, presión y humedad.

03 / IMPLEMENTACIÓN

Frontend y API intermedia segura

React gestiona la interfaz y la Geolocation API; Netlify Functions ejecuta la capa Express que valida consultas, protege la clave y normaliza la respuesta de OpenWeather.

04 / DESAFÍO

Unificar entradas, estados y seguridad

El reto fue integrar ciudad y coordenadas en un solo flujo, mantener coherentes carga, errores y unidades, y aplicar caché, timeout y límite de solicitudes en el servidor.

Resultado

Experiencia meteorológica full-stack publicada en Netlify, responsive y accesible, con la clave de OpenWeather aislada del navegador.
