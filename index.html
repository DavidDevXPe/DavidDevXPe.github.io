TipoAplicación frontend
Fuente de datosPokeAPI
PublicaciónVercel
01 / OBJETIVO

Simplificar la exploración de Pokémon

Crear una experiencia de consulta que permitiera encontrar información de Pokémon sin recorrer manualmente todos los resultados disponibles en PokeAPI.

02 / SOLUCIÓN

Un flujo de consulta completo

La aplicación combina ingreso como entrenador, búsqueda por nombre, filtro por tipo y paginación. Cada tarjeta presenta el tipo y las seis estadísticas principales del Pokémon.

03 / IMPLEMENTACIÓN

Estado, navegación y datos separados

Construí la interfaz con componentes reutilizables en React, utilicé Redux Toolkit y React Redux para el estado global, React Router para las vistas y Axios para consumir PokeAPI.

04 / DESAFÍO

Coordinar datos asíncronos y controles

El reto fue mantener coordinadas la búsqueda, el filtrado y la paginación, mientras transformaba la respuesta de la API en tarjetas consistentes y fáciles de consultar.

Resultado

Aplicación frontend publicada en Vercel, con una demo funcional y el código fuente disponible públicamente en GitHub.

CASO DE ESTUDIO 02 / PUBLICADO

Rick and Morty App

Abrir demo ↗ Ver código
TipoAplicación frontend
Fuente de datosRick and Morty API
PublicaciónVercel
01 / OBJETIVO

Relacionar ubicaciones y residentes

Facilitar la exploración de las ubicaciones del universo de Rick and Morty y de los personajes asociados a cada una mediante una consulta directa.

02 / SOLUCIÓN

Información contextual en una sola vista

El usuario consulta una ubicación por identificador y obtiene su nombre, tipo, dimensión y residentes. Los personajes se presentan en tarjetas y se organizan mediante paginación.

03 / IMPLEMENTACIÓN

Lógica asíncrona reutilizable

Construí la interfaz con React y Axios. Encapsulé las peticiones y los estados de carga y error en un custom hook, apoyándome en useState, useEffect y useRef para controlar la interacción.

04 / DESAFÍO

Organizar conjuntos variables de residentes

El reto fue coordinar el ciclo de las peticiones asíncronas, reutilizar la lógica de consulta y presentar cantidades distintas de personajes sin perder claridad en la navegación.

Resultado

Aplicación frontend publicada en Vercel, con una demo funcional y el repositorio disponible públicamente en GitHub.

CASO DE ESTUDIO 03 / PUBLICADO

Weather App

Abrir demo ↗ Ver código
TipoAplicación frontend
Fuente de datosOpenWeatherMap
PublicaciónVercel
01 / OBJETIVO

Convertir una ubicación en información útil

Transformar las coordenadas actuales del usuario en una consulta meteorológica clara, con los datos principales reunidos en una sola interfaz.

02 / SOLUCIÓN

Condiciones actuales y cambio de unidad

La aplicación muestra ciudad, país, descripción, temperatura, viento, nubosidad, presión y humedad. También permite alternar la temperatura entre Celsius y Fahrenheit.

03 / IMPLEMENTACIÓN

Dos procesos asíncronos conectados

Utilicé la Geolocation API para obtener coordenadas, Axios para consultar OpenWeatherMap y useState y useEffect para actualizar la interfaz y controlar la unidad seleccionada.

04 / DESAFÍO

Mantener los datos y unidades coherentes

El reto fue encadenar la geolocalización con la consulta meteorológica y transformar correctamente la temperatura entre Kelvin, Celsius y Fahrenheit sin alterar los datos recibidos.

Resultado

Aplicación frontend publicada en Vercel, con una demo funcional y el código fuente disponible públicamente en GitHub.
